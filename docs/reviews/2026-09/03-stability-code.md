# Work brief 3 — Stability, code and release engineering

Source: whole-game review of 2026-09-02 (hands-on playtest plus thirteen subsystem code reads; their findings are folded into this brief). Line numbers were checked at commit `1fba7f4`; re-grep before editing.

## Session kickoff (read first)

- Server: `apps/game-server/ltg_game_server/` (`app.py` REST + WebSocket, `session.py` authoritative state + pacer + confirms, `snapshot.py` seat-filtered contract, `jobs.py` background generation, `appctl.py` quit/update, `launch.py`). Engine: `apps/combat/ltg_combat/`. Schema: `core/ltg_core/schema.py`. Client: `apps/game-ui/src/`.
- Tests: `.venv/bin/python -m pytest tests/ -q` (1221 passing, 78 s). The suite writes into the REAL `content/` and `loadouts/` and its cleanup deletes files that appear mid-run: never run it while hosting. `tests/conftest.py` holds a session flock for that reason.
- Distribution facts that shape this brief: a non-technical Windows player runs a full clone and updates in-app (`core/ltg_core/selfupdate.py`: git fetch + `merge --ff-only` + pip); `apps/game-ui/dist` is committed so a Node-less install can serve it; `content/` is git-tracked live content the game itself writes; `loadouts/` is per-install and gitignored.
- Baseline hygiene: no CI (`.github/` absent), no ruff/mypy/eslint config, zero client tests, `tsc` runs only inside `npm run build`, 43 broad `except Exception` in Python.

## Item 3.1 — Harden the LAN session

### Problem (verified)
- **Confirm branch has no error handling.** `app.py` ~1010-1019: `answer_confirm` → `_resolve_confirm` → the registered action (`sc.visit`, `start_adventure`, `_fire_choice`, `_accept_rewards`) can raise `ValueError` (stale location, "leave the conversation first", "that choice is not available"). The exception escapes the `while True` loop; the `finally` runs `remove_client`, which closes the answering client's socket and releases their seats. Nothing blocks other verbs while a confirm is pending, so the race is easy: A starts Ride Out, A opens an NPC conversation, B clicks Yes, B is disconnected. Compare the guarded `submit_action` branch (~975-988).
- **Pacer has no exception guard.** `_drain_paced` (`session.py` ~244-288): an exception in `apply_action` or a hook kills the task silently; `start_pacer` (~235-243) restarts it on the next client message and it crashes at the same step. The fight soft-locks with no message. `_AUTO_CAP` exhaustion (~259) is also silent. `asyncio.get_event_loop()` at ~241 should be `get_running_loop()`.
- **Other frames that kill the connection:** non-dict or malformed JSON frames (~945), non-numeric `id` (~1013), a list `character_ids` (~951), `town` with a list payload (`town_verb` catches only `ValueError`, ~1004). Only the official client speaks the protocol, but the consequence (dropping seats) is disproportionate.
- **No durable player identity.** Reconnect mints a new `client_id` with no seats (`ws.ts` ~33-38 reconnects every 1 s; `store.ts` has no token, no auto-reclaim). A wifi blip releases seats instantly (`remove_client` ~144-149), the priority holder is unowned, the confirm `player_count` changes, and a friend's "Claim all" can take the seat.
- **Server restart strands everyone.** The fatal error frame (`app.py` ~918-928) makes the client close the socket and show a 3.5 s toast; `App.tsx` ~112-116 then renders "Connecting…" forever (`App` keeps its own `sessionId`; `store.ts` ~250-253, ~305-317). "Return to the menu" hits the same dead end. No `popstate` handling.
- **A crash mid-fight loses the fight.** `to_jsonable` (`serialize.py` ~31-43) is one-way; there is no `GameState` deserializer; saves are only at boundaries (`runs.py` ~379-386) and restore recomposes from a seed (`adventure.py` ~488-544). Quit is `os._exit` after 0.4 s (`selfupdate.py` ~152-157) with no goodbye frame.
- **Worker threads mutate session state without the lock:** `jobs.generate_sync` (`jobs.py` ~67-88) calls `attach_adventure` / `set_state` from `to_thread`; `_materialize_task` (`app.py` ~221-222) and `_new_arc_sync` (~228-235) mutate the scenario from the worker; art painters call `set_spoil_art` / `set_cast_art` from threads (`art.py` ~663-683, ~727-729, ~855) while broadcasts read the same objects on the loop.
- **`load_save` is sync** (`app.py` ~357-404), so `_scenario_async` (~184-201) finds no running loop and runs the LLM materialization inline, blocking the HTTP response for minutes with a "…" button.
- **Failed act materialization wedges the town.** `materialize()` (`scenario.py` ~296-306) leaves `act=None` with the raw exception in the splash; `retry_job` (`app.py` ~1021-1024) re-fires only the adventure job; the only recovery is Save → Load (`app.py` ~387-395). `TownScreen.tsx` ~647-674 shows an enabled Continue and "Accept a quest first" forever.
- Minor: `SessionManager` never garbage-collects (`session.py` ~853-882); loading a wrap-up save appends a duplicate `adventure_end` save at load time (`session.py` ~123-124, ~305-319 with `adventure.complete` restored True at `adventure.py` ~501); the confirm timer imports `time` via `__import__` (~255); `remove_client` does not re-evaluate a pending confirm.

### What to build
1. **Guards (half a day):** wrap the confirm resolve and the whole ws dispatch in `try/except ValueError` (and a last-resort `except Exception` that logs the traceback) that sends an `error` frame and `continue`s; never let the `finally` drop a client for a server-side rule error. Give the pacer the same guard as `submit_action`: log, broadcast an `error` frame ("the engine hit a fault; last good state shown"), stop retrying. Log loudly on `_AUTO_CAP` exhaustion. Validate message shapes with small Pydantic models per message type.
2. **Durable identity + seat grace + presence:** the client generates a `player_token` (localStorage, like pane sizes) and sends it on connect; the server keys seats by token, holds them 90 s after a drop, re-binds on reconnect, counts players (not sockets) for confirms, and ships presence ("Ari dropped — holding seats") in the seats payload. Show names in the seat ribbon.
3. **Restart recovery:** on a fatal session error render a real state with "Load your last save" (newest save of the most recent run from `/api/runs`, or a remembered `run_id`); lift `sessionId` into the store; handle `popstate`; fix "Return to the menu".
4. **Mid-fight recovery:** implement `from_jsonable` for `GameState` (about 15 dataclass constructors plus `Card.model_validate` / `TypeAdapter(List[Effect])`; re-link `PendingChoice.candidates` by id, see `state.py` ~868-870), a golden round-trip test over the autoplay corpus, and an autosave at every priority stop (or an append-only action journal `(phase_seed, actor, index, mana)` replayed from the last boundary save, which preserves the no-save-scum rule). Send a goodbye frame on Quit.
5. **Thread discipline:** compute in the worker, return the result, apply on the loop under `async with session.lock()`; make `load_save` `async def` so hooks schedule tasks instead of running inline.
6. **Materialization retry:** a `retry_materialize` verb wired to the splash and console; an `act_start` save before materialization with `act_present: False`; a player-facing message instead of `str(exc)`.
7. Minor: reap sessions with zero clients after N minutes when `state is None` or `result` is set; seed `_end_saved = adventure.complete` on construction from a save.

### Acceptance
- A two-socket WebSocket test (see 3.2 step 3) covering: claim, submit, pass, the confirm race above, a garbage frame, disconnect-and-rejoin within grace (seats retained), server-side ValueError (client stays connected, gets an `error` frame).
- Kill the server mid-Phase II, restart, load: the fight resumes at the last priority stop (or replays the journal) rather than the phase boundary.

## Item 3.2 — Ship safely to the Windows player

### Problem (verified)
- **No CI, no lint, zero client tests.** `pyproject.toml` root holds only `testpaths`; `apps/game-ui/package.json` ~7-9: `build` = `tsc --noEmit && vite build`, nothing else gates.
- **Stale committed client bundle.** `apps/game-ui/dist` last committed in `c8d9113` (2026-08-30 18:17) predates the client source change in `1fba7f4` (19:37, the TopRibbon seat-claim fix); the working tree holds an uncommitted rebuild. `launch.py` ~44-52 compares mtimes (meaningless on a fresh clone) and serves dist as-is without Node (~60-69). `46269da` shows the same pattern.
- **918 MB of PNG art in git.** `git ls-files content/art` = 564 PNGs (1.63 MB average, 511 added in August); `.git` = 1.0 GB; art is written raw (`art.py` ~335) and never resized or converted; repaints add blobs forever (`_write_image` ~315-336). About 75 files (135 MB) are orphaned (towns whose JSON no longer exists). A first clone for the Windows player is ~1 GB and every update pulls every painting.
- **Updater vs live-written content.** The game writes, edits and deletes tracked files under `content/` by design (`content.py` ~43-58, ~816-832); `git merge --ff-only` (`selfupdate.py` ~85) refuses whenever upstream touches any such path, and `_ff_failure` (~107-149) can only say "send your game admin the details". No stash, no reset, no test of the updater. `_SCAN_DIRS` (~54-58) already supports priority ordering.
- **Tests sweep the real content dirs.** `conftest.py` ~17-42 documents it; `test_design_update_10.py::_isolate` ~64-85 deletes every new JSON in `CONTENT_DIR` / `LOADOUTS_DIR`; `test_game_server.py` ~150-171, ~285-296 writes into them with `finally: unlink`. `test_art.py` ~16-32 already shows the `tmp_path` monkeypatch pattern. The session flock uses `fcntl` (no Windows).
- **Unpinned dependencies on an untested interpreter.** `requirements.txt` is editable installs + floors; package deps are floors only; dev venv is Python 3.9.6; `WINDOWS_INSTALL.md` ~12-16 says download the newest python.org release; `apply_update`'s pip has no `--upgrade` and no constraints (`selfupdate.py` ~92-103).
- **Drive-by REST.** `app.py` ~32-37: `CORSMiddleware(allow_origins=["*"], allow_methods=["*"])` on a `0.0.0.0` server; unauthenticated `POST /api/quit`, `POST /api/update/apply` (`appctl.py` ~22-41), `DELETE /api/runs/…`, `DELETE /api/characters/…`, `DELETE /api/encounters/…`, `PUT /api/llm/settings` (the API key). A bare POST from any page open in any LAN browser can end the table.
- **No release-path tests:** `selfupdate.py`, `launch.py`, `launch_all.py`, `appctl.py`, `ltg_deckbuilder.update` have zero test imports; the deckbuilder's "Update Game Character" deletes unvalidated drafts from disk (`apps/deckbuilder/ltg_deckbuilder/app.py` ~369-405, ~429-447).
- **Generation transport errors are not retried.** `_chat` is called outside the repair `try` in all three loops (`llm.py` ~1874-1876, ~2247-2249, ~2782-2784), so one 429/5xx/timeout fails a quest-accept job; type-shape faults (`TypeError`/`AttributeError` at ~1440, ~1483, ~1616) escape `except ValueError` and become HTTP 500 on the REST generate endpoints (`app.py` ~513-516, ~565-568). Encounter generation uses `_chat`'s 120 s default timeout against a 24k-token budget (~1780, ~1874).

### What to build
1. **Test isolation (first):** an autouse fixture in `conftest.py` that monkeypatches `content.CONTENT_DIR`, `content.LOADOUTS_DIR` (different dirs) and `art.ART_DIR` to `tmp_path`, then delete the flock and the "don't play while testing" caveat; enables `pytest -n auto` and Windows runners.
2. **One CI workflow** (`.github/workflows/ci.yml`): `pytest -q` on Python 3.9 and 3.13; `npm ci && npm run build`; `git diff --exit-code apps/game-ui/dist` (or stop tracking dist and have `apply_update` fetch a built release asset whose hash is recorded in the repo); `ruff check` (start with a permissive config: unused imports, `BLE001` for the broad excepts, `B` bugbear); branch protection on `main` so the player's `origin/main` only receives green merges.
3. **A two-socket WebSocket test** with Starlette's `TestClient.websocket_connect` (~80 lines) driving `ws_endpoint`, `_drain_paced`, the confirm timer, malformed frames and reconnect; plus a `selfupdate` test over a temp bare repo (`git init --bare` upstream, clone, monkeypatch `REPO_ROOT`, assert `check_update()["behind"]`, assert `_ff_failure` names a dirty path).
4. **Pin the environment:** `constraints.txt` from `pip freeze`; launchers and the updater use `pip install -c constraints.txt -r requirements.txt`; `requires-python = ">=3.9,<3.14"` until CI proves newer.
5. **Art out of git history's growth path:** convert on save to WebP at a bounded size (~150-300 KB; `_EXT` already accepts webp, `art.py` ~59), and either move `content/art` to git-lfs or ship art as a release asset fetched on demand (the `/art/` URL space already abstracts location). Delete the 75 orphans. Consider a one-time history rewrite only if the owner agrees (it changes every collaborator's clone).
6. **Shipped vs local content split:** a gitignored `content_local/` searched first in `_SCAN_DIRS`; the game writes there on player installs (a `LTG_AUTHOR_MODE` env or setting keeps the dev machine writing to `content/`); the updater then never collides. Add a "reset shipped content" self-service path for the rare collision.
7. **Close the drive-by hole:** CORS only under `--dev`; a host token printed at launch and required (header) for quit, update, delete and settings routes; `Origin`/`Host` checks.
8. **Generation resilience:** wrap `_chat` in a bounded retry with backoff for 429/5xx/timeouts (distinct from model-repair attempts); catch `TypeError`/`AttributeError` from the gates as repair turns; give the encounter path a real timeout; coerce deterministic faults (unknown class, missing dials, `supertypes` spelling) in code instead of re-emitting 20k tokens.
9. Deckbuilder: write the full authoring loadout on "Update Game Character" (let the game filter `validated` at load) or keep a sibling `<id>.draft.json`; return 422 with `_format_errors` from `/api/loadout/{name}` instead of a raw pydantic 500.

### Acceptance
- CI is green on a clean clone; pushing a client change without rebuilding dist fails CI.
- `pytest` can run while a server is hosting without touching `content/`.
- A player install that edited a shipped encounter still updates cleanly.
- `curl -X POST http://host:8020/api/quit` from another origin is rejected without the token.

## Item 3.3 — Make the contracts explicit

### Problem (verified)
- **Schema accepts misspelled keys.** `extra="forbid"` is set only on `ActionTarget` (~241), `Reinforcement` (~2564), `Escalation` (~2588), `EncounterObjective` (~2611) in `core/ltg_core/schema.py`. Every effect model, `Card`, `Cost`, `Item`, `Character`, `Loadout` silently accepts `ammount=5`, `durration="encounter"`, `efects=[]` with defaults. For a pipeline where an LLM writes cards, items and enemy verbs this is the biggest silent-corruption vector.
- **Refs and numerics are unvalidated.** `Ref` (~320-335) validates only `mult`; `REF_VALUES` (~344-379) is the declared closed registry; `_ref_value` (`engine.py` ~4389-4430) raises `ValueError` at resolution. `Stun(intents=-3)`, `Revive(to_fraction=5.0)`, `Sap(amount=-2)`, `CreateToken(count=-1)`, `Card(level=-5)` all validate; `lints.py` ~56-67 reads only `amount`.
- **The log is an untyped side channel.** ~148 `_log(st, "<literal>", **data)` call sites emit ~150 distinct `Event.type` strings (`engine.py` ~7885); the client switches on ~35 of them by string (`fx.ts` ~256-474) with ad-hoc data keys, which is why the stun FX never renders; nothing tests `fx keys ⊆ engine types`.
- **Three hand-kept shapes of one contract:** cockpit `serialize_state` (`serialize.py` ~868-888) vs game `build_snapshot` (`snapshot.py` ~339-466) vs `types.ts` (918 lines, "mirrors snapshot.py" by hand). Drift already exists: `ObjectiveView.kind` (`types.ts` ~226) lacks `"deadline"`; `LegalAction.kind` comment (~368) is stale; `snapshot.py` ~363-371 patches `targets` in after the fact. The serializer duplicates engine value functions and has diverged (`serialize._mitigate_value` ~429-435 can return 0; `engine._mitigate_value` ~2689-2700 is `max(1, …)`; `_defend_value` duplicated at ~438-443 vs ~2936-2940).
- **Adding a verb touches 6-8 files** and eight parallel classification sets in the engine: `_TARGETLESS` (~3949), `_CARD_ZONE_VERBS` (~3956), `_STACK_FACING` (~430), `_REACHES_DOWNED` (~4187), `CORPSE_LEGAL_EFFECTS` (schema ~1488), `_STAT_CONTINUOUS` (~3487), `_REAPPLIED_CONTINUOUS` (~3662), `_DAMAGE_KINDS` (~1345), plus `RESOLVERS` (~5874), `_apply_static` (~3490-3648, the file's largest function), `translation.RENDERERS`, `_effect_site_label` (~7672), `lints.py`, the deckbuilder's `CORPSE_KINDS` copy (`app.js` ~984), and `_HOSTILE_KINDS` / `_CONTROL_KINDS` in `serialize.py` (~114-133). Action modifiers are described three times (`schema.ACTION_MODIFIERS` ~782-807, `translation._ACTION_MOD_PHRASE` ~884-894, `serialize._ACTION_MOD_TAG` ~366-372). The schema docstring (~10-14) says a new verb is three steps and names a module that no longer exists.
- Schema fields resolvers silently ignore: `Taunt.duration` (`_r_taunt` ~5543 never reads it; cleared at `_end_step` ~2069); similar on `RemoveKeyword`/`Counters` duration (the resolvers never read them).
- `ScenarioRun` (~1,300 lines) hand-restores every field in `restore()` (~1257-1301) with ad-hoc migrations; `SAVE_SCHEMA_VERSION` is still 1 despite new blocks.

### What to build
1. **Schema hardening:** `model_config = ConfigDict(extra="forbid")` on `EffectBase`, `TargetDescriptor`, `Card`, `Cost`, `Item`, `ItemStatic`, `Character`, `Loadout`, with a `_prune`-style pre-pass for the known legacy keys (`source_name`, `ignore_source`, `preset`, `archetype`, `original_text`, `needs_translation`); a `field_validator("ref")` against `REF_VALUES ∪ {"$…"}`; non-negative / bounded validators for `intents`, `to_fraction`, `amount`, `count`, `generic`, `level`; run every stored loadout and content file through it once and fix what breaks.
2. **Typed event registry:** `EVENT_TYPES: dict[str, RequiredKeys]` in the engine; `_log` asserts against it in debug/test; export the union to the client (a generated `events.ts`); a test that every `fx.ts` case names a registered type and reads only its declared keys. Then tag `damage` with `mode` and delete the label map (brief 2 item 2.1 step 6).
3. **One snapshot contract:** Pydantic `Snapshot*` models (or TypedDicts) in one module used by both `serialize_state` and `build_snapshot`; `model_json_schema()` → `json-schema-to-typescript` in the client build to generate `types.ts`; a golden test that `build_snapshot` validates against the schema over the autoplay corpus. Import the engine's `_mitigate_value` / `_defend_value` in `serialize.py` instead of duplicating.
4. **Verb traits table:** `VERB_TRAITS[kind] = {targetless, card_zone, stack_facing, reaches_downed, corpse_legal, continuous_form, damage, hostile, control, enemy_legal, renderer}` in `schema.py`, read by engine, serializer, lints, the deckbuilder specs and the LLM gate; collapse the eight sets; fix the schema docstring; then honour or remove the ignored `duration` fields.
5. **Merge the enemy/party forks where cheap:** a shared `_push_intent` for `_swing_instead` and `_execute_intent` (~1890-1918 vs ~1955-1975), a pure `_build_default_attack` + thin `_file_slot` writer to end the save/restore tuple dance in `_declare_enemy_intent` (~863-875, ~1878-1885), a `RoundSlot` dataclass for the four parallel per-round fields.
6. `ScenarioRun.restore`: bump `SAVE_SCHEMA_VERSION`, move field lists to one place (a dataclass or Pydantic model for the scenario block), and add a migration test from the five saves under `saves/`.

### Acceptance
- A card JSON with a misspelled key or unknown ref is rejected at authoring with a field path; no engine `ValueError` from authored data is reachable at resolution.
- `types.ts` is generated, not edited; CI fails on drift.
- Adding a test verb touches schema (class + traits + renderer) and the engine resolver only.
